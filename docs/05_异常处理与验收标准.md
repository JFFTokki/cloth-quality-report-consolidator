# 异常处理与验收标准

## 0. 第一规则：繁体先转简体

- 任何异常判断前，必须先确认报告原生文本和OCR文本已转换为简体识别副本；繁体报告不得因未先转换而被归为表头未匹配、字段未识别或检测项未识别。
- 原始繁体页面文字或原始行仍须保留，避免转换后失去审计依据。

## 1. 异常类型

### PDF下载失败

- 保留原URL和下载错误信息。
- 不生成虚假检测结果。
- 在`质检全项目明细`中生成异常记录，标记为`下载失败`并记录具体错误。

### PDF文本不足

- 原生文本少于300个字符时记录并自动触发OCR，不得直接结束解析。
- OCR成功并提取到检测项时，处理状态为`已解析（OCR）`。
- OCR未执行、OCR引擎报错、OCR后文本仍不足必须分别标记为`OCR待处理`或`OCR失败`，不得统一写为`未识别检测项`。

### 表格、布局和表头识别异常

- 报告文本充足但无法提取网格表格时，必须继续尝试无网格文本定位；两种方式都失败才标记`无可识别表格结构`。
- 已发现表格但机构使用的同义表头未匹配时，标记`表头字段未匹配`，详情列出未匹配原文。
- 已识别检测项列但没有可靠结果/判定列时，标记`缺少结果或判定列`。
- 所有候选项名均被清洗规则排除时，标记`检测项被有效性规则排除`，并保留候选原文。

### 未识别检测项

- 报告已读取，但未匹配到任何已定义或候选检测项目。
- 需要检查是否为文本提取错乱、扫描件、表格结构异常或真正的新检测项。
- 如果能从报告中定位到清晰的检测项名称，应优先归为`新增检测项待确认`，不要简单归为未识别。

### 新增检测项待确认

- 报告中出现原有规则未覆盖的检测项或新别名时记录。
- 保留原始检测项、简体检测项、可能的统一检测项、源报告单号、PDF报告号、PDF链接和上下文。
- 同步写入`质检全项目明细`的待复核或异常记录，状态标记为`新增候选`或`待复核`。
- 在人工确认前不能强行合并到含义不同的既有项目。
- 人工确认后应更新标准检测项或别名规则，作为后续全量处理的长期规则。

### 缺失判定或结果

- 已识别检测项，但实测值、标准要求或判定无法可靠提取时记录。
- 不猜测结果，不用“符合”补空值。
- 可在明细中保留检测项和来源，结果字段留空并标记待复核。

### 机构名称宽松展示

- 机构名称字段不进入人工确认；不得输出`机构名称待确认`。
- 必须先执行首页顶部整宽报告头解析，不得因机构名不在固定左侧或图章不在固定右侧而跳过。
- 机构名称与CMA/CNAS文字处于同一视觉行时，必须先按OCR文字块独立提取，不得因同行存在资质文字而丢弃机构名。
- 优先输出法定全称；无法取得全称时，直接输出报告页面可识别的检测机构自身简称、检测品牌、域名标识或已验证版式标识，并在诊断中注明`宽松展示`及识别依据。委托方、客户、生产单位、供应商及其品牌不得作为机构回退值，普通说明句也不得作为机构名称。
- 报告中完全没有可用机构文字时输出`未识别`并记录原因，不转为待确认；不得把明确标注为委托方、客户、生产单位或供应商的名称当作出具机构。
- 机构名称的宽松识别或未识别不应阻止可靠检测项进入`质检全项目明细`和主表汇总。

### CMA/CNAS标识待复核

- CMA和CNAS必须分别判定；`TESTING`、`中国认可`、`国际互认`或`资质认定`不得单独作为标识存在的强证据。
- CMA图形仅识别成`MA`或`MMA`时，必须同时具有其下方清晰的12位资质编号、有效坐标和横向重叠关系才可记为`有`；手机号、普通业务编号或未对齐编号不得作为组合证据，单独出现时仍为`待复核`。
- 首页顶部报告头OCR失败、未执行、或OCR完成但没有读到强文字/组合证据时，必须写`待复核`及具体原因，不得写`未发现`。

### 同项结果差异

- 同一货号、颜色、统一检测项在多份PDF中出现不同结果。
- 各报告结果按报告号并列保留，不自动覆盖。

### 无效货号

- 货号为空、为`0`或明显为占位值时，不应进入主展示表。
- 保留源表行号、源报告单号、颜色、PDF链接和详情，便于业务侧补正真实货号。
- 不得把无效货号自动归并到其它货号。

## 2. 数据验收

- 选中款号数量与目标一致。
- “货号+颜色”行数与颜色拆分结果一致；源记录未标明颜色时，应作为`未标明颜色`记录保留。
- 多链接单元格中的每个PDF均进入下载清单和来源索引。
- 同一货号同一颜色的全部有效源记录均进入主表数据池，最后修改时间不作为排除旧报告的依据。
- 旧报告中的独有检测项不得因存在更新报告而丢失。
- 明细中的每条记录均包含货号、颜色、标准检测项和PDF链接。
- 横向统一检测父项数量与实际识别结果一致；子项不得被误拆为大量横向列。
- 无法可靠归属的短词、OCR残片和上下文不足项目必须标记`待确认归属`，保留在明细和映射中，但不进入横向正式检测项列。
- 原规则未覆盖的新检测项应进入`质检全项目明细`的待复核或异常记录，不得静默丢弃。
- `质检全项目明细`中的处理状态必须细分原因，不得只用笼统的“解析异常”。
- `质检全项目明细`应能区分下载失败、PDF文本不足、未识别检测项、新增检测项待确认、缺失判定或结果、机构名称未识别、同项结果差异、无有效货号和无PDF链接；报告出具机构名称不得写`机构名称待确认`。
- `质检全项目明细`还必须区分PDF打开失败、OCR待处理、OCR失败、PDF文本异常、无可识别表格结构、表头字段未匹配、缺少结果或判定列、检测项被有效性规则排除和项名不完整待复核。
- 同一PDF关联多条源记录时，明细表可保留源记录关系，但质量统计必须按PDF URL去重，同一PDF不得被重复计数。
- 每个PDF的异常详情必须包含至少一个可执行诊断指标，例如原生/OCR字符数、表格数、表头候选、被排除项数或引擎错误；不允许只写“新逻辑未识别”。
- 合格项目不显示多余的“符合”。
- 不合格项目必须显示“不符合”。
- 货号显示为完整数字，不带`SKU-`且不使用科学计数法。
- 标准父项不得包含Unicode私用区字符、控制字符或不可见字符；任何只含符号和标点、没有语义文字的名称一律禁止进入横向主表。
- 检测项开头的项目符号必须在语义归并前清除；不得因为连字符拆分而把项目符号误判为父项。
- CTTC等无网格版式不得输出由定位碎片拼成的连字符父项；同一检测项内部文字必须先连续拼接，只有真实父项/子项关系才允许使用父子项分隔符。
- 全角/半角百分号及其它单位写法必须统一；括号内仅为单位时不得保留在父项名称中。
- 圆括号、方括号及全角括号必须按同一结构解析；其中的材料、部位、方向和条件应作为子项，不得造成同类父项分裂。
- 无意义字符检查必须基于Unicode字符类别独立执行，不得与清洗逻辑共用有限符号名单。

## 3. 回归检查

每次调整解析或归并规则后至少复核：

- `200426108006`的pH值为`5.7`。
- `200426108006`的甲醛含量为`未检出`。
- `200426108006`的胀破强度为`757N`。
- `208426103216`的多个PDF链接均被处理。
- `201426107206`的全部有效报告均进入识别范围，旧报告中的独有检测项不得丢失。
- `pH值（其他）`归并为`pH值`。
- `抗起毛球`保持原统一名称，不改为`起毛起球`。
- `标识标签*`、`标识标签`、`标识`统一归为`标识标签`。
- `材质鉴别[帮面]`与`材质鉴定（帮面）`必须归入同一父项，`帮面`保留为标准子项。
- `残脂率`、`残脂率(%)`、`残脂率(％)`必须统一为`残脂率`，百分号只进入单位字段。
- `U+F0A2-二氨基二苯甲烷`等PDF私用区项目符号必须清除，具体物质归入`可分解致癌芳香胺染料`父项；不得出现纯符号父项。
- 羽绒成分表格必须完整识别`羽绒成分测定-含绒量`、`羽绒成分测定-含绒量极限偏差`、`羽绒成分测定-绒子含量`、`羽绒成分测定-长毛片含量`、`羽绒成分测定-异色毛绒`、`羽绒成分测定-绒丝+羽丝`、`羽绒成分测定-杂质`、`羽绒成分测定-陆禽毛`，不得只保留父项或子项短词。
- 羽绒表格中因换行被拆开的`含绒量极限偏差`必须还原为完整名称。
- 源表货号为`0`的记录进入`质检全项目明细`异常记录，不进入`货号检测总览`。

## 4. 工作簿验收

- 工作簿只包含2个业务工作表：`货号检测总览`、`质检全项目明细`。
- `货号检测总览`按货号展示基础检测和功能性检测父项数量及清单。
- `质检全项目明细`保留结构化结果、待复核、异常、审计摘要、原始文本和诊断信息。
- 不包含早期样表的`检测结果查看`、`检测汇总`、`检测明细`、`项目映射`、`源报告索引`、`异常日志`、`繁体复核`、`质量检查`，除非用户明确要求生成历史结构对照表。
- 所有表头、长文本和关键结果可见，无明显截断。
- 不冻结窗格；表格筛选按钮正常。
- 扫描公式错误：不得出现`#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`、`#N/A`。
- 对全部工作表进行视觉渲染检查。
- 自动渲染结果若为`1×1`或空白占位图，不得视为视觉检查通过，必须明确记录并改用外部无界面渲染抽查代表区域。
