## 当前生产流程

1. 源表读取：`pipeline/qc_all/select_source.py` -> `source_records.json`
2. PDF 下载：`pipeline/qc_all/download_pdfs.py` -> `download_manifest.json` 和本地 PDF
3. PDF 文本与 OCR：`pipeline/qc_all/extract_text.py` -> `pdf_text.json`
4. 报告头元数据识别：由 `extract_text.py` 调用 `report_header.py`
5. 表格和检测项抽取：`pipeline/qc_all/extract_table_items_checkpoint.py` -> 每 PDF 原子结果和 `table_items_rows.jsonl`
6. 检测项归并：`pipeline/qc_all/build_100_sku_parent_child_report.py` -> `report_data.json`
7. 校验和导出：`validate_records.py` -> `export_leader_workbook.mjs`

其它 `pipeline/qc_all/` 脚本可能是测试、人工复核、历史导出或诊断工具。是否属于生产流程以本节和 `docs/04_处理流程与运行说明.md` 为准。

## 规则来源与优先级

当前规则来源包括：Python 明确规则、人工确认 Excel、`docs/` 业务规则，以及 JavaScript 分类和工作簿导出规则。优先级为：

1. 最新明确人工规则；
2. 代码中的最新明确规则；
3. 已确认人工映射种子；
4. 保守自动规则；
5. 无法确认则进入待复核。

新增规则必须修改可复用规则源、增加回归测试并更新集中版本常量。功能性关键词和版单号清洗目前跨语言执行，继续修改时必须同时验证解析端和导出端；本轮不做无测试的大规模迁移。

## 本轮建议处理决策

- 已采纳：TLS 与下载资源保护、严格交付门禁、真实日历、稳定来源关系、可重试 checkpoint、哈希和解析版本、匿名回归测试、实现状态文档。
- 渐进采纳：全部工作表、Excel 超链接、缓存远端重验证、规则源集中、跨平台 OCR、导入副作用清理。
- 暂不采纳：整体重写解析器、一次性迁移所有规则到 YAML、更换 OCR 技术、删除历史脚本或历史产物。

## 未来 Skill 目标

通用 Skill 负责定义适配器契约、标准记录结构、可靠性门禁、来源追溯、未知版式处理和交付验收；项目扩展负责季度范围、源表列别名、人工映射、机构版式和业务分类。通用 Skill 不应声称自带一个能识别所有机构报告的万能解析器。
