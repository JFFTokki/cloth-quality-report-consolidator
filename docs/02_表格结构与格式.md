# 表格结构与格式

当前交付以领导版本为主轴，默认只生成两张业务工作表：`货号检测总览`和`质检全项目明细`。早期8张工作表样表仅作为历史回归参考，不再作为新输出的结构规范。

字段和视觉规则的可执行权威同时维护在`quality-report-consolidator/references/schema.md`；脚本变更后必须同步本文件和该schema。

## 0. 第一规则：繁体先转简体

- 报告出现繁体文字时，必须先将全文转换为简体，再进行字段、表头、检测项、结果和元数据识别；繁体原文另行保留用于追溯。

## 1. 货号检测总览

用途：按货号查看检测覆盖情况，区分基础检测和功能性检测。

字段顺序：

1. 货号
2. 检测项目总数
3. 基础检测项目数
4. 基础检测项目清单
5. 功能性检测项目数
6. 功能性检测项目清单
7. 涉及报告数
8. 报告单号
9. 检测报告文件名
10. 对应版单号
11. 样品类型
12. 总体判定
13. 待复核项目数
14. 异常报告数

格式规则：

- 一行代表一个货号。
- 只统计去重后的统一检测父项；材料、部位、方向、条件、组分和具体物质保留在明细表，不单独计为总览项目。
- 只有`已确认`或保守验证通过的`自动归并`项目进入总览；`待复核`和`解析残片`不进入项目数量和清单。
- 货号、报告单号和版单号按文本保存，避免科学计数法或前导字符丢失。
- 新增辅助列用低饱和灰色标识，不再使用明显橙色。

## 2. 质检全项目明细

用途：完整审计底表。每个结构化检测结果、待复核记录、异常记录和必要审计摘要都在这里保留来源、原文、诊断和归并结果。

字段顺序：

1. 记录ID
2. 记录类型
3. 来源表行
4. 报告序号
5. 报告单号
6. 检测报告文件名
7. 报告内编号
8. 来源货号/款号
9. 小类
10. 报告签发日期
11. 报告内货号/款号
12. 颜色
13. 报告内版单号
14. 面料/物料编号
15. 样品类型
16. 来源判定
17. PDF页码
18. 表序号
19. 项目序号
20. 项目类别/表标题
21. 检测项目
22. 统一检测父项
23. 标准检测子项
24. 检测方法/判定依据
25. 技术要求/限值
26. 实测/测试结果
27. 单项判定/结论
28. 单位
29. 是否有国际认证
30. CMA标识
31. CNAS标识
32. CAS号
33. 报告出具机构名称
34. 报告限/检出限
35. 备注
36. 项目原始行/页面完整原文
37. 检测报告来源URL
38. 简体检测项目
39. 归并状态
40. 归并证据（AN列）
41. 报告签发日期识别状态（AO列）
42. 报告签发日期异常原因（AP列）
43. CMA识别证据/异常原因（AQ列）
44. CNAS识别证据/异常原因（AR列）
45. 是否进入总览
46. 检测分类
47. 本地PDF路径
48. 解析器版本
49. 规则版本
50. 诊断信息
51. 处理状态
52. 来源工作表
53. 来源单元格

字段位置规则：

- `报告签发日期`放在`报告内货号/款号`之前。
- `小类`紧跟`来源货号/款号`。
- `报告签发日期识别状态`、`报告签发日期异常原因`、`CMA识别证据/异常原因`、`CNAS识别证据/异常原因`四个灰列统一放在归并证据列之后，即AO:AR。
- `颜色`紧跟`报告内货号/款号`。
- `统一检测父项`、`标准检测子项`紧跟`检测项目`。
- `是否有国际认证`放在`CMA标识`和`CNAS标识`之前；任一标识为`有`时结果为`是`，否则为`否`。
- `CMA标识`、`CNAS标识`放在`CAS号`之前。
- `报告出具机构名称`放在`CAS号`之后。
- `处理状态`、`来源工作表`、`来源单元格`移到最右侧。

记录类型建议使用：`项目判定汇总`、`检测结果明细`、`补充检测结果`、`表级结论`、`表格说明`、`报告信息/表格原文`、`页面完整原文`、`待复核`、`异常`、`审计摘要`。

`归并状态`可使用`已确认`、`自动归并`、`自动新增`、`自动归入父项（子项类型未完全识别）`、`自动归入领域父项`、`待确认归属`、`待复核`、`解析残片`。只有已确认或保守自动归并/自动新增/安全自动归入的父项可以进入总览；`待确认归属`、`待复核`、`解析残片`不得进入`货号检测总览`。

## 3. 报告级元数据

同一PDF只提取一次报告级元数据，并继承到该PDF的所有明细记录：

- `报告签发日期`：确认值格式为`yyyy-mm-dd`；识别状态为`已识别`、`未发现`或`待复核`。空值和不确定值必须填写异常原因。同一优先级标签下出现多个日期时采用较晚日期并标记`已识别`，异常原因列保留全部候选和选择说明。
- `CMA标识`、`CNAS标识`：取值为`有`、`未发现`或`待复核`，仅表示报告中是否出现相应标识，不验证证书有效性或检测项目是否在认可范围内。
- `是否有国际认证`：仅由CMA/CNAS标识汇总；任一项为`有`即为`是`，其余组合均为`否`，不代表证书有效性或具体项目在认可范围内。
- `CMA识别证据/异常原因`、`CNAS识别证据/异常原因`：对应值为`未发现`或`待复核`时不得为空；识别为`有`时也应记录证据来源。
- `报告出具机构名称`：采用宽松展示口径。优先输出报告头、页眉页脚、印章或OCR文字块中可稳定识别的法定全称；无法取得全称时，允许直接输出报告页面可识别的检测机构自身简称、检测品牌、域名标识或已验证版式标识，不要求人工确认。委托方、客户、生产单位、供应商及其品牌不得作为机构回退值。报告中完全没有可用机构文字时输出`未识别`，不得留空或写`机构名称待确认`；识别层级和证据保留在诊断信息中。
- `CAS号`、`报告限/检出限`：从表头、专用列或同一结果行中提取，不得用固定空白占位。

## 4. 统一视觉规范

- 使用领导版本视觉模板：隐藏网格线、启用表格筛选按钮、Carlito 11号、长文本换行并顶部对齐。
- 标题行使用深蓝`#17365D`、18号白色粗体。
- 说明行使用浅黄`#FFF4CE`和深褐`#7A4E00`文字。
- 表头使用蓝色`#1F4E78`、白色粗体居中。
- 数据区保留领导版蓝白交替底色、判定色、记录类型色和功能项条件色。
- 不冻结窗格。
- 相对领导原始版本新增的辅助列使用灰色：表头`#D9D9D9`、正文`#F2F2F2`。
- `颜色`、`统一检测父项`、`标准检测子项`、`报告签发日期`、`CMA标识`、`CNAS标识`、`报告出具机构名称`使用原表正常颜色，不做特殊强调。

## 5. 历史8表样表

历史样表曾包含`检测结果查看`、`检测汇总`、`检测明细`、`项目映射`、`源报告索引`、`异常日志`、`繁体复核`、`质量检查`八张工作表。它们仍可用于核对旧基准数据和回归项，但新交付不得以这8张表替代领导版两张业务表。
