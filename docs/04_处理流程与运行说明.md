# 处理流程与运行说明

## 0. 第一规则：繁体先转简体

任何原生文本或OCR文本进入报告字段、表头、检测项、结果和元数据识别前，必须先全文转换为简体。缓存同时保留原始繁体页面文字或OCR块文字，正式明细通过原始行、页面原文或诊断字段保持追溯。

## 1. 当前入口

- 主输入：项目根目录`质检报告汇总.xlsx`。
- 工作目录：默认`pipeline/qc_all/`；抽样或隔离复跑时通过`QC_WORK_DIR`指定。
- 解析器：`extract_table_items_checkpoint.py`。
- 当前100款样表生成器：`build_100_sku_parent_child_report.py`。
- 羽绒完整项名回归：`test_down_items_complete.py`。

首次运行或系统升级后，先配置并验证项目环境：

```bash
scripts/setup_environment.sh
```

该脚本创建项目内`.venv`、安装`requirements.txt`中的Python依赖，并实际执行一次PDF渲染与macOS Vision OCR自检。系统还必须通过Homebrew安装Poppler（提供`pdftoppm`和`pdfinfo`）。正式处理统一使用`.venv/bin/python`；未通过预检时`extract_text.py`会在批处理前立即退出并列出具体缺项，不再把笼统环境错误写入逐PDF结果。macOS Vision必须在普通终端或获准的非沙箱进程中运行；若自动化运行环境限制Vision创建识别任务，启动门禁会整批停止并明确报告权限原因。

`input/质检报告汇总.xlsx`是交接副本；当前脚本`select_source.py`实际读取项目根目录文件。

## 2. 处理链路

1. `select_source.py`筛选`2026Q4`，拆分颜色与单元格内全部PDF链接。
2. `download_pdfs.py`按URL去重下载，并记录每份PDF的真实下载状态。
3. `extract_text.py`读取全文原生文本或OCR文本后，先生成完整简体识别副本并保留原文，再执行“首页顶部报告头”专用解析；顶部整宽区域不限定左右位置，按OCR文字块及内容识别机构名、CMA和CNAS，字段未解决或原生文本不足时调用macOS Vision OCR。机构名优先回查页眉、页脚和全文直接出现的法定名称；无法取得全称时按宽松展示规则采用页面可识别的检测机构自身简称、检测品牌、域名标识或已验证版式标识，委托方、客户、生产单位、供应商及其品牌不得作为机构回退值；完全无可用文字时写`未识别`，不再进入人工确认。
4. `extract_table_items_checkpoint.py`依次尝试原生网格、无网格文本定位和OCR定位，输出逐项明细与解析诊断。
5. `build_100_sku_parent_child_report.py`应用人工确认种子和父项/子项归并，并在同款号、同报告、同样品、同一标准项目存在“仅结论行+具体数值行”时保留带具体数值及检测方法/判定依据的明细，生成`report_data.json`作为结构化中间数据。
6. `quality-report-consolidator/scripts/validate_records.py`校验记录完整性后，`quality-report-consolidator/scripts/export_leader_workbook.mjs`按领导版视觉规则生成`货号检测总览`和`质检全项目明细`两张业务表。
7. 执行回归、公式错误扫描和两张业务表视觉检查。

页面候选判断采用多信号评分，不再要求页面必须同时出现一组固定关键词。放宽入口不等于放宽结果：只有能可靠定位检测项及结果/判定关系的行才进入明细。

## 3. 运行示例

在项目根目录执行。先生成源数据和PDF文本：

```bash
.venv/bin/python pipeline/qc_all/select_source.py
.venv/bin/python pipeline/qc_all/download_pdfs.py
.venv/bin/python pipeline/qc_all/extract_text.py
```

重置并分批抽取检测项；重复第二条命令，直到输出中的`remaining`为0：

```bash
.venv/bin/python pipeline/qc_all/extract_table_items_checkpoint.py --reset
.venv/bin/python pipeline/qc_all/extract_table_items_checkpoint.py --limit 300
```

生成当前结构的100款中间数据：

```bash
QC_DATA_PATH="tmp/<新工作目录>/report_data.json" \
.venv/bin/python pipeline/qc_all/build_100_sku_parent_child_report.py
```

旧8表工作簿导出只作历史对照；确需生成时显式设置`QC_LEGACY_XLSX=1`和`QC_OUTPUT_PATH`。默认不要把旧8表文件作为交付。

校验并导出领导版两表工作簿：

```bash
.venv/bin/python quality-report-consolidator/scripts/validate_records.py \
  tmp/<新工作目录>/report_data.json \
  --downloads tmp/<新工作目录>/download_manifest.json

node quality-report-consolidator/scripts/export_leader_workbook.mjs \
  tmp/<新工作目录>/report_data.json \
  outputs/test_V2/<新文件名>.xlsx
```

执行羽绒项名完整性回归：

```bash
.venv/bin/python pipeline/qc_all/test_down_items_complete.py
```

若系统Python缺少依赖，应使用工作区提供的Python运行环境，不要修改系统Python。OCR默认开启；仅在明确不需要OCR时设置`QC_ENABLE_OCR=0`。

复用既有PDF文本及OCR结果时，可用系统路径分隔符连接多个缓存文件；程序只对缓存中缺失或需要OCR刷新的PDF重新提取：

```bash
QC_TEXT_CACHE_PATHS="tmp/<批次1>/pdf_text.json:tmp/<批次2>/pdf_text.json" \
.venv/bin/python pipeline/qc_all/extract_text.py
```

首页报告头OCR默认开启并写入缓存；只有在机构名、CMA、CNAS都已由可靠原生文本解决时才不运行视觉OCR。明确不需要该检查时可设置`QC_ENABLE_HEADER_OCR=0`，但未完成图像检查的CMA/CNAS不得记为“未发现”。

报告内货号、版单号和面料/物料编号等编码字段必须兼容多种PDF排版形态。版单号以`版单号：`或`版单号:`为起点，标签后出现的全部内容都属于版单号，直到遇到下一个中文字符；也就是首个中文字符之前的字母、数字、标点和连接符均完整保留。PDF在内容中插入的空白统一移除，例如`426FZ- BS-925`规范为`426FZ-BS-925`。

版单号不再限制为英文字母、数字及`-`、`/`、`_`连接符，也不得因空格或其他非中文符号提前截断。例如`版单号：ABC- 中文说明`提取为`ABC-`，`版单号：AB.12+CD(3)中文说明`提取为`AB.12+CD(3)`，`版单号：125FB-UZ-801面料编号：—`提取为`125FB-UZ-801`。报告头规则升级后必须提升`HEADER_PARSER_VERSION`，禁止沿用旧缓存中的污染值；领导版导出前还必须按同一中文边界再次清洗，避免旧`report_data.json`中的历史污染值重新进入Excel。

CMA/CNAS之前的报告签发日期按标签优先级识别：`报告签发日期/签发日期`、`出具日期/Date of Issue`、`报告日期`、`检测日期/检验日期`。只在更高优先级无可靠候选时使用低优先级标签；日期范围使用结束日期。同一优先级出现多个日期时，统一采用较晚的日期作为更新日期，并在候选诊断中保留全部日期和选择原因，不再因此标记`待复核`。

CMA图形被OCR识别为低置信度`MA`或`MMA`时，只有在其下方同时存在清晰的12位资质编号，两个识别块都有有效坐标且横向范围真实重叠时才记为`有`；编号中的空格和常见分隔符可规范化，单独的`MA`、`MMA`、手机号、普通业务编号或未对齐编号仍进入`待复核`。

## 4. 关键中间文件

- `source_records.json`：源记录、颜色、全部URL和采用关系。
- `download_manifest.json`：逐PDF下载状态、路径、大小和错误。
- `pdf_text.json`：逐页原生/OCR文本、报告号、机构和OCR诊断。
- `table_items_rows.jsonl`：逐PDF、逐颜色、逐检测项的抽取结果。
- `table_items_state.json`：分批处理进度和累计统计。
- `report_data.json`：领导版两表导出的结构化输入，包含明细、异常、源记录索引、报告级元数据和统计摘要。

这些文件可在`QC_WORK_DIR`下重建，不是业务最终结果。

## 5. 归并顺序

1. 保留原始检测项。
2. 转为简体名称，并在语义判断前执行Unicode兼容规范化、PDF私用字符清洗、全半角单位统一和括号结构提取。
3. 应用人工确认工作簿`outputs/manual_review/2026Q4_按检测项目列抽取_同类项待判断.xlsx`中的已确认映射。
4. 应用代码中的最新明确规则；较新的用户规则优先于旧人工种子。
5. 先按同页编号章节、合并单元格、同一检测块和检测标准恢复上下文，再判断名称的父项/子项语义角色。
   - CTTC等无网格版式必须先恢复逻辑列：按字段坐标和结果/判定列位置还原检测项目列，将同一检测项内被文字定位拆开的片段连续拼接，再添加真正的父项与子项分隔符；不得把同一词语内部碎片用`-`连接成父项。
6. 拆为统一检测父项和标准子项，并保存置信度、归并证据和是否进入横向主表。
7. 已知父项但子项类型未完全恢复时自动归入父项；完整新项目自动新增；明显解析残片排除；只有父项和领域都无法确定时才标记`待确认归属`。

抽取与上一批不重复、且单一主要样品类型不超过指定上限的随机样本：

```bash
.venv/bin/python pipeline/qc_all/select_random_100.py \
  --work-dir tmp/<新工作目录> \
  --seed <新随机种子> \
  --exclude-skus-file tmp/<上一批>/sample_skus.json \
  --max-per-primary-sample-type 30
```

只复跑已知问题款号时，可用空格、逗号或换行传入12位款号；检测项抽取和结构化构建均使用同一个范围，避免误跑其他款号：

```bash
QC_ONLY_SKUS="201326102102 200125132201" \
QC_WORK_DIR="outputs/runs/<新工作目录>" \
  .venv/bin/python pipeline/qc_all/extract_table_items_checkpoint.py --reset
QC_ONLY_SKUS="201326102102 200125132201" \
QC_WORK_DIR="outputs/runs/<新工作目录>" \
  .venv/bin/python pipeline/qc_all/extract_table_items_checkpoint.py --limit 300
QC_ONLY_SKUS="201326102102 200125132201" \
QC_SAMPLE_LIMIT=all \
QC_DATA_PATH="outputs/runs/<新工作目录>/report_data.json" \
QC_WORK_DIR="outputs/runs/<新工作目录>" \
  .venv/bin/python pipeline/qc_all/build_100_sku_parent_child_report.py
```

`QC_ONLY_SKUS`只应配合独立的新运行目录使用。只要该变量已设置，若没有解析出12位款号、或任一款号不在当前源记录中，流程必须立即失败，不得退化为全量运行。

## 6. 解析状态

每个PDF必须保留下载、打开、原生文本、OCR、表格、表头、候选项、排除项和明细行数等诊断。主状态按以下顺序确定：

下载/文件问题 → PDF打开问题 → OCR/文本问题 → 表格或布局问题 → 表头问题 → 结果列问题 → 项名完整性/有效性问题 → 新项候选 → 兜底未识别。

已抽取部分明细但仍有页级异常时标记`部分解析`；不得仅根据明细行数是否为0统一写成“未识别检测项”。

## 7. 扩大范围前的门槛

- 先审查`待确认归属`的高频项目，确认后写回归并规则。
- 新机构表头、新产品类型和新增别名先在小样本验证。
- 羽绒父项与8个成分子项回归必须通过。
- 工作簿公式错误扫描与两张业务表视觉检查必须通过。
- 新输出放入新文件，不覆盖历史结果。
