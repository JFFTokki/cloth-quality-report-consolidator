# 输出文件规范

本规范用于统一质检报告整理项目的输出文件夹、文件名和留痕方式。目标是让业务交付文件易找、工程复跑结果可追溯，并确保新输出不覆盖历史结果。

## 0. 第一规则：繁体先转简体

所有输出均以“报告繁体文字先全文转为简体再识别”为首要规则，且必须在明细或运行归档中保留原始繁体页面文字、原始行或诊断证据。

## 1. 输出目录分层

`outputs/`下按用途分为四类：

```text
outputs/
  deliverables/          # 对外或领导版正式交付
    2026Q4/
  review/                # 人工复核材料、待确认和异常清单
    2026Q4/
  runs/                  # 每次脚本运行的完整归档
    <运行时间>_<任务名>/
  legacy/                # 历史旧结构，只读保留
```

目录用途：

- `outputs/deliverables/<季度>/`：只放可直接交付或发送的业务文件，默认包括领导版两张业务表工作簿及其必要校验结果。
- `outputs/review/<季度>/`：放人工判断、待确认归属、异常清单、候选检测项和复核材料。
- `outputs/runs/<运行时间>_<任务名>/`：放一次复跑产生的完整证据链，包括中间数据、导出工作簿、校验日志、检查结果和预览图。
- `outputs/legacy/`：放历史全量输出、旧8表结构或早期试行样表。历史文件不得作为当前交付结构的默认验收依据。

当前已有`outputs/manual_review/`可逐步迁移到`outputs/review/2026Q4/`；已有`outputs/<uuid>/`可视为历史运行归档，后续新运行统一使用`outputs/runs/`。

## 2. 正式文件名格式

对外交付和复核文件统一使用以下格式：

```text
<季度>_<范围>_<用途>_<状态>_<规则版本>_<生成日期>.<扩展名>
```

字段说明：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 季度 | `2026Q4` | 数据所属季度或项目批次。 |
| 范围 | `随机100款`、`指定12款`、`全量`、`含指定8款` | 数据范围，不使用模糊描述。 |
| 用途 | `领导版两表`、`待确认归属`、`异常清单`、`数据底稿`、`预览图` | 文件主要用途。 |
| 状态 | `正式交付`、`复核版`、`验证版`、`草稿` | 文件可用程度。 |
| 规则版本 | `R20260720`、`mapping-r3` | 归并规则、人工映射或导出规则版本。暂未单独编号时用生成日规则版本。 |
| 生成日期 | `20260720` | 文件生成日期，格式为`YYYYMMDD`。 |

示例：

```text
2026Q4_随机100款_领导版两表_正式交付_R20260720_20260720.xlsx
2026Q4_随机100款_待确认归属_复核版_R20260720_20260720.xlsx
2026Q4_随机100款_异常清单_复核版_R20260720_20260720.xlsx
2026Q4_随机100款_领导版两表_验证版_R20260720_20260720.inspect.ndjson
```

## 3. 运行归档命名

每次完整复跑必须建立独立运行目录：

```text
outputs/runs/<YYYYMMDD_HHMMSS>_<任务名>/
```

任务名使用短横线或下划线连接，保持简短、可读：

```text
outputs/runs/20260720_153012_random100_header-v2/
outputs/runs/20260720_171830_full_export_mapping-r3/
```

运行目录内建议保留：

```text
report_data.json
download_manifest.json
export.log
validate_records.log
workbook.xlsx
workbook.inspect.ndjson
workbook.qa.ndjson
preview_overview.png
preview_detail.png
RUN.md
```

其中`RUN.md`记录本次运行的输入范围、关键命令、规则版本、输出文件、校验结果和已知问题。业务交付文件名不承载过长的调试说明，详细原因写入`RUN.md`或日志。

## 4. 状态词使用规则

- `正式交付`：已完成数据校验和工作簿视觉检查，可对外发送。
- `复核版`：供人工判断或业务复核，不代表最终交付。
- `验证版`：用于检查新逻辑、新字段、新样式或回归，不对外发送。
- `草稿`：临时探索或未完成导出，只能放在运行目录内，不得进入`deliverables/`。

`deliverables/`中原则上只放`正式交付`文件；如必须放验证文件，应在同目录`README.md`或`RUN.md`说明原因。

## 5. 禁止和避免的命名

文件名不得使用以下模糊词作为主要版本依据：

```text
最新版
最终版
新逻辑
效果验证
再改版
颜色列调整
V2
V3
```

确需表达变更原因时，应转为稳定字段：

- `新逻辑`改为具体规则版本，例如`R20260720`。
- `效果验证`改为状态`验证版`。
- `颜色列调整`写入`RUN.md`，文件名保留用途为`领导版两表`。
- `V2`、`V3`只在已有外部版本号或人工映射版本号明确时使用，例如`mapping-r3`。

## 6. 输出与覆盖规则

- 新输出必须使用新文件名或新运行目录，不得覆盖历史结果。
- 正式交付文件必须能追溯到对应`outputs/runs/<运行时间>_<任务名>/`中的`report_data.json`、校验日志和检查结果。
- 缓存、中间数据和旧产物未经确认不得删除。
- 不得只修改输出Excel来修正规则；新的人工明确规则应写回归并规则或人工确认来源，再重新导出。
- `待确认归属`、`待复核`和`解析残片`相关材料进入`review/`或运行目录，不进入横向正式列。

## 7. 推荐导出路径

领导版两表正式交付：

```text
outputs/deliverables/2026Q4/2026Q4_随机100款_领导版两表_正式交付_R20260720_20260720.xlsx
```

人工复核文件：

```text
outputs/review/2026Q4/2026Q4_随机100款_待确认归属_复核版_R20260720_20260720.xlsx
```

运行归档文件：

```text
outputs/runs/20260720_153012_random100_header-v2/workbook.xlsx
outputs/runs/20260720_153012_random100_header-v2/report_data.json
```

脚本复跑时可先导出到`outputs/runs/<运行时间>_<任务名>/workbook.xlsx`；验收通过后，再按正式文件名导出或复制到`outputs/deliverables/<季度>/`。
