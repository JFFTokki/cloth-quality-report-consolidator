# 质检报告整理分析

本项目从源Excel读取款号、颜色、质检结论及PDF链接，自动下载和解析质检报告，将繁体文字转换为简体，归并不同质检机构的同义检测项目，最终生成可查看、筛选、追溯的Excel工作簿。

当前主流程以领导版本为核心，默认生成两张业务表；早期`2026Q4`随机100款8表样表只作为解析与归并回归参考，不再作为最终交付结构：

- 输入文件：`质检报告汇总.xlsx`
- 当前业务工作表：`货号检测总览`、`质检全项目明细`
- 当前导出结构：先生成`report_data.json`，再用`quality-report-consolidator/scripts/export_leader_workbook.mjs`套用领导版视觉规则导出Excel。
- 历史全量输出仍保留在`outputs/V2/`，不要把它当作最新归并规则的验收结果。

该100款样表的基准数据为：512条源记录、469份PDF、14,996条检测明细、204条货号+颜色汇总、259个横向检测父项；另有466条明细标记为`待确认归属`，不会进入横向正式检测项列。

## 运行环境

首次运行或macOS升级后执行：

```bash
scripts/setup_environment.sh
```

正式流程使用项目内`.venv/bin/python`。环境检查会验证Python依赖、项目内置并由安装脚本链接的Node工作簿导出依赖、Poppler PDF渲染、Swift、动态定位的macOS SDK及一次真实Vision OCR；任一必要条件缺失时会在批处理前明确失败。Vision自检需在普通终端或获准的非沙箱进程运行，受限沙箱会被识别为环境失败并在读取PDF前停止。

## 当前确认原则

1. 报告出现繁体文字时，必须先将全文转换为简体，再识别报告字段、表头、检测项、结果和元数据；繁体原文另行保留用于追溯。
2. 一个单元格内的所有PDF链接都必须读取，不能只读取第一个。
3. 同一货号同一颜色必须读取和识别全部源记录中的全部PDF，不能只保留最后修改时间最新的报告。
4. PDF解析应依次尝试原生表格、无网格文本定位和OCR；不得因固定关键词缺失而直接跳过数据页。
5. 异常必须保留逐PDF诊断，区分下载、PDF打开、OCR/文本、表格布局、表头、结果列、项名有效性和项名完整性等原因，不再统一记为“未识别检测项”。
6. 羽绒成分必须保留完整的父项+子项名称，例如`羽绒成分测定-绒子含量`；不得只保留父项或脱离上下文的子项短词。
7. `货号检测总览`只统计已确认或保守自动归并的统一检测父项，并拆分基础检测与功能性检测。
8. 合格项目显示实测值，不重复显示“符合”；不合格项目必须显示判定。
9. 不同机构的同义检测名称归并为统一项目，但不改变检测含义。
10. 原始名称、简体名称、统一父项、标准子项、报告号、版单号、PDF链接、报告签发日期、CMA/CNAS识别证据、机构名称和CAS号必须可追溯。
11. 货号只显示数字，不添加`SKU-`，并使用固定整数格式避免科学计数法。
12. 最后修改时间只用于辅助排序和追溯，不作为丢弃旧报告或旧检测项的依据。
13. 横向统计只使用统一检测父项；材料、方向、条件、组分和具体化学物质保留为标准子项。无法可靠归属的内容进入待确认，不强行生成新横列。

## 2026Q4 检测项目同类项判断表

用户已更新的人工判断工作簿：

`outputs/manual_review/2026Q4_按检测项目列抽取_同类项待判断.xlsx`

该表按 PDF 表格中的`检测项目`列抽取检测项目，结果口径只取用户圈选确认的`检测结果`和`单项判定`两列，并保留 PDF 报告号、货号、颜色、PDF 页码和 PDF 链接。人工判断同类项后，再写回正式检测项目归并规则。

当同一检测项目因面料、部位、颜色组合或样品层不同而出现多个子项时，核心检测项目名称仍用于归并；括号、方括号中的差异内容，以及对应的检测结果和单项判定，应进入`检测结果细则`保留。
